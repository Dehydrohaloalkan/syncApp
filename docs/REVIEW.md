# Независимое ревью одностороннего протокола SyncApp

Дата: 11 октября 2026 года. Ревьювер — `gpt-6.1-sol`; проверены окончательные
исходники ядра, криптографии, Git, локального HTTP host, интерфейса и актуальная
документация. Производственные исправления выполнял отдельный кодер; ревьювер
передавал замечания и повторно проверял изменённый код. Этот отчёт заменяет
ревью прежнего двустороннего QR-прототипа.

## Результат проверки кода

Блокирующих замечаний к текущему одностороннему контракту не осталось.
Протокол версии 3 подключает две заранее подготовленные чистые исходные репы,
сверяет подписанный зашифрованный digest исходной базы и допускает независимые
истории Git. Публичный рабочий age-ключ переносится вручную текстом.

Work создаёт ключи и состояние локально, получает junk только через fast-forward
pull и не вызывает транспортные commit/push. Прямой запрос `push: true`
отклоняется в ядре; HTTP endpoint передаёт этот флаг тому же методу.
Apply меняет исходный индекс и файлы, Confirm/Recover сохраняют локальную связь
с единственным ручным рабочим коммитом. Квитанций, обратных пакетов, QR,
камеры и файловых transport-маршрутов в продукте нет.

Personal публикует следующие коммиты без подтверждения Work. Исходящий курсор
продвигается после успешного push. Интерфейс личной стороны не объявляет
рабочую базу проверенной: статус применения на другом устройстве ему неизвестен.

## Замечания, закрытые до финального прохода

- **Роль проекта в настоящем HTTP API.** HTTP serializer теперь возвращает
  `Personal`/`Work` строками, как ожидает интерфейс. Без этого настройки только
  локального JSON оставляли числовой Side в ответах host, и личный проект
  ошибочно получал рабочие действия. Браузерные ответы-заглушки скрывали дефект;
  добавлена проверка роли в настоящем `/api/session`.
- **Публикация посторонних данных.** Добавлен локальный манифест точных ciphertext
  и принадлежащих приложению transport-коммитов. Перед push проверяются все
  неопубликованные коммиты, их файлы, режимы, хеши, нейтральное сообщение и
  служебные author/committer. Проверка всей истории предотвращает публикацию
  посторонних данных даже после их удаления из конечного дерева.
- **Открытый дескриптор.** Публичный JSON имеет точную каноническую схему;
  неизвестные и дублированные свойства не публикуются. LF/CRLF допускаются для
  обычного Git checkout. Закреплённые ключи проверяются на Work при операциях
  и повторно после pull; удаление рабочего ключа после проверки базы тоже
  отклоняется. Повтор привязки того же рабочего ключа на Personal идемпотентен.
- **Переписанная подготовленная очередь.** Сохраняется префикс исходных коммитов
  и ChangeId. Amend/rebase этого префикса и уменьшение лимита ниже уже
  подготовленной очереди останавливаются до публикации конкурирующих пакетов.
- **Пути и размер объектов.** Проверяются отдельные transport-файлы, а не только
  каталоги; symlink/junction не проходят чтение и staging. Входящие encrypted
  объекты проверяются относительно лимита 64 MiB до загрузки в память.
- **Восстановление.** Pending ApplySession сохраняется перед изменением исходных
  файлов. Восстановление сверяет ветку, HEAD, индекс, digest и проверенный пакет;
  посторонние правки сохраняются. Для личного transport-коммита сохраняется
  намерение с parent и tree; повтор допускает только соответствующий этому
  журналу staged-набор или уже созданный нейтральный коммит.

## Проверки и границы

Финальный Linux-прогон 11 октября: Core **33/33**, HTTP **8/8**, browser **3/3**;
свежие Debug и Release собраны без предупреждений и ошибок. Ревьювер получил
команды и результаты отдельного тестера и координатора; подробности в
[TESTING.md](TESTING.md). Проверки используют временные исходные репозитории,
два clone junk и локальную bare-репу. Ревьювер не публиковал данные в настоящий
GitHub и не создавал коммитов в этом checkout.

Браузерный набор проверяет настоящий host и ресурсы; действия проектов и
недоверенные метаданные проверяются с подменёнными API-ответами. Это проверка
интерфейса, а не полный браузерный прогон криптографического подключения.

Windows 10, Windows 11 + WSL, реальные GitHub credentials, повреждение диска,
потеря питания и несколько одновременно работающих экземпляров не проверены.
Проверки путей не гарантируют защиту от враждебной конкурентной замены другим
процессом. Разрешение расходящейся junk-истории, ротация ключей, новые поколения,
LFS/submodules и нестандартные Git-фильтры остаются вне текущего сценария.
Состояние старого прототипа автоматически не мигрируется; для новых подключений
используется отдельный `SYNCAPP_DATA_DIR` с сохранением прежних ключей и данных.

## Дополнительное ревью встроенного age

20 ноября 2026 года независимо проверена замена `age`/`age-keygen` на
`AgeSharp 0.2.0-preview.7`. Замечаний к текущему производственному diff не осталось.
Используются только типизированные X25519 API: разбор ключей не вызывает
плагины или внешние процессы. Поддерживается прежний текст identity с комментариями
и LF/CRLF; генерация не меняет существующие ключи или регистрацию каналов.
Формат локальных файлов ключей, отпечатки, RSA-PSS-подпись контейнера и протокол
v3 сохранены. Полная расшифровка и проверка подписи завершаются до возврата payload.

При ревью исправлена очистка буфера: она теперь выполняется также при отказе
расшифровки позднего блока. Буфер выделяется сразу по размеру ciphertext,
чтобы рост `MemoryStream` не оставлял промежуточные копии открытого контейнера.

Исследован [исходный код закреплённой версии](https://github.com/pscheid92/AgeSharp/tree/v0.2.0-preview.7),
а не только README пакета. [Выбор AEAD](https://github.com/pscheid92/AgeSharp/blob/v0.2.0-preview.7/Age/Crypto/AeadCipher.cs)
использует управляемый BouncyCastle при `ChaCha20Poly1305.IsSupported == false`,
включая Windows 10 без платформенного ChaCha20-Poly1305. Загруженный пакет
сопоставлен с официальным NuGet: SHA-256 совпадает, repository commit в nuspec —
`1f52f1d7a4a5b9995da57cd888e1c4fc23bcde43`. Включённые пакеты не содержат
нативных runtime-библиотек или CLI-инструментов.

Команды и фактические результаты прогонов приведены в [TESTING.md](TESTING.md).
Этот проход ревью не запускал сборки параллельно с тестером. Проверка исходного
кода fallback не является запуском на Windows 10; Linux с доступным платформенным
ChaCha20-Poly1305 использует другой backend. Приложение и сторонняя библиотека
не проходили криптографический аудит; ревью не даёт такой гарантии.
