# Проверки SyncApp

Транспорт работает через GitHub/junk. Личная сторона создаёт подписанные зашифрованные baseline и пакеты и отправляет их по явному действию пользователя. Рабочая сторона только обновляет clone, проверяет baseline и принимает пакеты; применение меняет рабочую копию кода, а исходный коммит пользователь создаёт вручную. Рабочая сторона не создаёт транспортных коммитов, не отправляет их и не публикует подтверждения. QR- и файловый перенос не поддерживаются.

## Локальный прогон

Из корня репозитория:

```sh
dotnet build SyncApp.slnx
dotnet run --project tests/SyncApp.Tests.csproj --no-build
python3 tests/http_security.py
SYNCAPP_PLAYWRIGHT=/path/to/playwright \
SYNCAPP_CHROMIUM_PATH=/path/to/chrome-headless-shell \
  node tests/browser.cjs
```

Для браузерных тестов укажите локальные Playwright и Chromium. Core использует встроенную age-реализацию; CLI `age` и переменная `AGE_PATH` ему не нужны. Проверки используют только временные репозитории и локальный bare remote; они не обращаются к настоящему GitHub.

## Что проверяется

Интеграционный набор создаёт две независимые исходные репозитории, два junk-clone и локальный bare remote. Он проверяет ручную привязку age recipient и fingerprint, публикацию и проверку зашифрованного baseline, последовательность личных пакетов, применение и локальное подтверждение ручного коммита. Отдельные сценарии проверяют повтор push после отказа, сохранение ciphertext при отказе fast-forward pull, блокировку посторонних staged-файлов, отказ при несовпадающем baseline и recipient, порядок пакетов, восстановление после прерываний и отсутствие plaintext исходных путей, сообщений и содержимого в объектах junk.

Проверки также убеждаются, что Work отклоняет `push: true` до вызова Git push, а его junk clone не получает транспортных коммитов: HEAD следует только fast-forward от remote, index и worktree junk остаются чистыми. Применение меняет source worktree; после него пользователь вручную создаёт source-коммит и локально подтверждает его. В junk не появляются Work-пакеты или подтверждения. Проверяются неподтверждённые локальные junk-коммиты и сообщения коммитов, переписанная очередь, дескрипторы с LF и CRLF при `core.autocrlf`, дублированные JSON-поля, `.age` symlink, открытие зашифрованного CLI age-v1-вектора с комментированным legacy identity и шифрование/дешифрование многочастных объектов без CLI. HTTP-набор проверяет CSRF, Origin/Host, размер тела и удалённые QR/file-transfer маршруты. Браузерный набор проверяет отдельные действия Personal и Work, отсутствие у Work push-контрола, отсутствие загрузки файлов и QR-ресурсов, отсутствие внешних запросов и безопасный вывод недоверенных метаданных.

## Проверено в Linux

До перехода на встроенную age-реализацию Linux Debug/Release, HTTP (8 тестов) и browser (3 проверки) проходили с временными репозиториями и локальным bare remote. Эти результаты относятся к предыдущей версии криптографической реализации.

Для встроенной реализации Debug-сборка завершилась без предупреждений и ошибок. Core-набор прошёл 35/35 сценариев при удалённом `AGE_PATH`; отдельный 1 MiB roundtrip также задаёт `AGE_PATH` на несуществующий бинарник. Набор использует только встроенный код. Постоянный тестовый вектор с комментированным identity и подписанным age-v1 пакетом зашифрован независимым Go CLI age 1.0.0; runtime-зависимости на CLI нет.

Отдельная проверка в Windows 11 build 26200 с .NET SDK 10.0.113 прошла на чистом package cache: восстановление выполнялось из локального offline feed; Personal со старым Go CLI создала и опубликовала пакет, Work без `AGE_PATH` получил, расшифровал и применил его, затем пользовательский commit был подтверждён. Размер пакета был 155000 байт. Отдельно принят непарный публичный дескриптор канала p01. Windows 10 и WSL не проверялись в этом прогоне.

Фактически выполненные команды и локальные пути:

```sh
dotnet clean SyncApp.slnx
dotnet build SyncApp.slnx
env -u AGE_PATH dotnet run --project tests/SyncApp.Tests.csproj --no-build
python3 tests/http_security.py
SYNCAPP_PLAYWRIGHT=/tmp/syncapp-test-tools/browser/node_modules/playwright \
SYNCAPP_CHROMIUM_PATH=/home/alex/.cache/ms-playwright/chromium_headless_shell-1234/chrome-headless-shell-linux64/chrome-headless-shell \
  node tests/browser.cjs
dotnet build SyncApp.slnx -c Release --nologo
```

Результаты Linux-прогона не подтверждают поведение Windows или WSL. Для них нужен отдельный запуск на соответствующей платформе.
