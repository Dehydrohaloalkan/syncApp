# Восстановление локального применения

Актуальный контракт от 11 октября 2026 года: личная машина публикует
подписанные зашифрованные изменения в junk, рабочая только получает и применяет.
Начальную копию пользователь готовит отдельно; сетевых квитанций и импорта
архивов прежнего QR-прототипа в текущем сценарии нет. Основной план:
[PLAN.md](../PLAN.md).

## Журнал ApplySession

Перед фактическим применением сохраняются исходный HEAD, ожидаемый digest,
накопленные ChangeId, pending ChangeId и pending result digest. После применения
состояние обновляется повторяемо. Проект, канал и поколение хранятся в локальном
подключении; верифицированный пакет должен совпадать с журналом.

При перезапуске приложение проверяет ветку и фактическое состояние:

| Состояние | Поведение |
| --- | --- |
| HEAD прежний, индекс/файлы соответствуют прежнему результату | Pending-пакет ещё не применён; разрешить повтор |
| HEAD прежний, индекс/файлы соответствуют pending-результату | Добавить пакет в группу ровно один раз |
| Один новый обычный ручной коммит поверх исходного HEAD, чистая репа, дерево равно pending-результату | Восстановить группу и завершить локальное подтверждение |
| Другая ветка, посторонние правки, дополнительные коммиты или неверное дерево | Остановить восстановление, сохранить файлы и журнал |

«Коммит создан» проверяет итоговое дерево и сохраняет локальную CommitMap.
Повторное подтверждение возвращает существующую связь. Никакие файлы,
квитанции или transport-коммиты в рабочем clone junk не создаются.

## Приватные временные файлы

PrivateWorkspace создаёт каталоги под проверенным локальным состоянием,
вне junk и исходников. TMPDIR/TEMP/TMP не определяют место открытого age-ключа
или пробного Git-индекса. На Unix применяются права 0700/0600, на Windows
защищённый ACL текущего пользователя до записи секретных scratch-данных.
Удаляются только собственные расходные файлы операции.

## Публикация личной стороны

Локальный журнал известных объектов связывает относительный transport-путь
с хешем зашифрованных байтов. Пакеты создаются атомарным переименованием.
Перед transport-коммитом сохраняются родительский HEAD и дерево индекса.
Если commit прерван, повтор разрешается только при совпадении сохранённого
дерева и исходного HEAD; после успешного commit фиксируется его принадлежность
приложению. В push допускаются только известные коммиты с проверенными
содержимым, нейтральным сообщением и identity.

Отказ push не продвигает курсор отправленных исходных коммитов; перезапуск
и повтор должны использовать прежние ChangeId и готовые байты.

Pull использует fast-forward без stash/reset/force. При конфликтах локальные
пакеты должны сохраняться, а операция останавливаться. Автоматическое разрешение
расхождений transport-истории и произвольные аварийные точки публикации
не входят в текущую гарантию восстановления.

## Проверки

Тестер проверяет прерывание до/после записи пользовательских файлов, накопленную
группу, ручной коммит после сбоя, неверный результат и идемпотентное подтверждение.
Сетевые сценарии используют два clone junk и локальную bare-репу. Проверяются
отказ push, повторная публикация, сохранение неизвестных staged-файлов и рабочая
сторона без транспортных записей.

Фактические результаты: [TESTING.md](TESTING.md), независимое ревью:
[REVIEW.md](REVIEW.md). Контрольные точки не моделируют повреждение диска,
потерю питания или несколько экземпляров. Windows/WSL проверяются отдельно.
