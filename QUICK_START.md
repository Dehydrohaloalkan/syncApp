# Краткая инструкция SyncApp

Приложение работает на двух машинах: личная публикует зашифрованные изменения
через GitHub-репу `junk`, рабочая только получает и применяет их.

## Запуск

На обеих машинах нужны Git, age/age-keygen и .NET SDK 10. Из папки SyncApp:

```bash
dotnet run --project SyncApp/SyncApp.csproj
```

Откройте **http://127.0.0.1:5055**. Если age отсутствует в PATH, задайте `AGE_PATH`
полным путём к нему; age-keygen должен лежать рядом.

## Первое подключение

1. Подготовьте одинаковый начальный код в Git-репах на обеих машинах. Репозитории
   должны быть чистыми и иметь начальный коммит; SHA коммитов могут различаться.
2. Отдельно клонируйте `junk` на обе машины и настройте upstream транспортной
   ветки. Личной стороне нужен доступ на публикацию, рабочей достаточно чтения.
   Исходники, junk и локальное состояние должны находиться в отдельных папках.
3. На личной нажмите **«Новый проект»**, укажите каталог проекта в junk,
   существующую папку исходников и пароль локальных ключей.
4. Введите пароль, включите **«Отправить транспортный коммит в GitHub»** и
   нажмите **«Синхронизировать junk»**.
5. На рабочей подключите свою ветку к тому же каталогу проекта в junk,
   указав независимо проверенный отпечаток личного устройства.
6. Скопируйте показанные рабочим приложением **публичный age-ключ и его
   отпечаток** на личную. Секретный ключ не переносится.
7. На личной вставьте эти данные в **«Подключить рабочий ключ»** и нажмите
   **«Закрепить ключ»**.
8. Синхронизируйте личную машину с отправкой, затем рабочую. Приложение проверит
   совпадение начального кода перед применением изменений.

## Обычная работа

1. **На личной:** пишите код и создавайте обычные Git-коммиты в подключённой ветке.
2. В приложении введите пароль, выберите количество пакетов (`0` — все),
   включите отправку в GitHub и нажмите **«Синхронизировать junk»**.
   Без отметки отправки пакеты останутся подготовленными локально.
3. **На рабочей:** нажмите **«Синхронизировать junk»**, затем
   **«Проверить входящие»** и **«Применить»** у следующего изменения.
4. Можно последовательно применить несколько изменений. После этого
   самостоятельно создайте один рабочий Git-коммит с накопленным результатом
   и нажмите **«Коммит создан»**.

Рабочая машина ничего не отправляет в GitHub. Обратных квитанций нет;
личное приложение знает о доставке пакетов, но не об их применении.

После прерывания применения используйте **«Восстановить операцию»**.
Не переписывайте уже подготовленные личные коммиты через amend/rebase.

При переходе со старого QR-прототипа используйте новый `SYNCAPP_DATA_DIR`,
сохранив прежние ключи и состояние. Подробности — в [README.md](README.md).
